## 实际范围与检查

检查并迁移主站全部 16 个 HTML 入口：玄关、作品列表／详情、关于、文章列表／详情、便签、工作台、门牌、工具墙、院子、邻居、说明书、视频灵感室、图片灵感室、404。房间目录仍为 10 间。盘点见 `inventory.json`。

样式中的系统字体栈、背景、图标、SVG、图片、动画、悬停和减少动态效果规则均保留。19 份原 CSS 在 `src/styles/` 和构建产物中与原版逐字节相同；另有一份很小的 `react-shell.css` 处理挂载点和原工作台入口样式。13 份有效数据／纯逻辑文件没有改动。图片／图标相关文件（包含原图许可）也逐字节核对一致。证据见 `integrity.json`。

提示词优化器是原本已独立构建的 Vue 子站，不属于待迁移的传统 HTML 实现。本次保留其固定源码版本、独立资源及原有模型设置，未将第三方工程改写为 React。当前主站只新增 React／React DOM 两个运行依赖；Vite、Playwright 为开发依赖，没有 UI 组件库、Tailwind、后端、数据库、登录或云端服务。React 运行依赖许可见 `public/THIRD-PARTY-LICENSES.txt`。

## 组件和数据边界

| 位置 | 职责 |
| --- | --- |
| `src/main.jsx`、`src/pages/registry.js` | 识别旧地址，按当前页面异步加载 JSX 和对应控制器，再挂载 React |
| `src/App.jsx` | 组织跳转正文入口、导航、页面、页脚，接入页面生命周期 |
| `src/components/Navbar.jsx` | React 菜单状态、关闭与焦点恢复；沿用原导航 DOM 和类名 |
| `src/components/Footer.jsx`、`SiteMark.jsx` | 共用房间平面图、订阅入口及站标 |
| `ProjectCollection.jsx`、`ProjectCard.jsx` | React 作品分类状态、卡片渲染、查询参数与旧锚点兼容 |
| `ToolShortcut.jsx` | 工作台三处工具入口的共享结构 |
| `src/pages/*.jsx` | 各页原有内容与实际分区，例如首页 Hero、房间路径、概览、作品、关系图、最近记录 |
| `src/controllers/` | 封装原有搜索、文章、关系图、便签、提示词、时钟、动效、查看器与 PWA 行为 |
| `src/runtime/` | 监听器、定时器、观察器、临时下载链接的清理；构建时 SW 模板 |
| `src/data/site.js` 与有效 `assets/*-data.js` 等 | 内容与交互之间的兼容边界；继续支持原本的离线维护生成器 |
| `src/styles/`、`public/` | 当前样式源文件与当前静态资源 |

这次没有为了改框架重写已工作的提示词／便签业务规则。它们仍由原生控制器负责空列表、输出区域和非受控表单值，React 负责页面结构和生命周期。不是把整个站塞进 `App.jsx`，也没有用 `dangerouslySetInnerHTML` 加载整页 HTML。兼容的 `window.SITE_*` 数据接口暂时保留。

维护时，不能让 React 和原生控制器同时更新同一区域的子节点。未来逐个转为 React 受控组件时，需同时移除对应控制器。当前没有客户端路由库：各 HTML 地址仍是独立页面，页面离开即结束其控制器生命周期；开发修改采用整页更新，未引入 Fast Refresh 或开启 StrictMode 的重复 effect 行为。

## 样式、资源和缓存接线

Vite 默认合并 CSS 会改变原站部分覆盖顺序，因此构建及开发启动时从 `src/styles/` 原样同步公共 CSS 至 `public/assets/`，由每页按原顺序加载。生成的 CSS 副本已加入忽略规则；只修改 `src/styles/`。开发监听避开 `.tmp`、历史备份和研究目录；依赖扫描只检查 16 个有效 HTML 入口。

默认 `base` 为 `/MyWeb/`。保留 `.html`、查询参数和锚点。构建后的 404 含对应 `<base>`，可处理 GitHub Pages 的嵌套缺失地址；不依赖 SPA 回退规则。根路径部署可用 `npm run build -- --base=/`。

当前完整发布包为 165 个文件：主站 120（包含 `.nojekyll`）、独立优化器 45。主站缓存从原来的 105 项变为 113 项，由实际构建资源自动生成，包含异步页面／控制器分包。feed、sitemap、robots、许可文本不进 SW 缓存；优化器维持独立范围。缓存名称使用内容版本加构建哈希，避免继续命中传统站缓存。

`npm run build` 可单独构建主站，在本机存在已校验的优化器产物时一起复制；没有时明确提示。`npm run build:pages` 为完整发布入口，缺少优化器产物会失败。GitHub Actions 已接入主站 `npm ci --ignore-scripts`、数据检查及 Vite 构建，仍构建原固定版本优化器。发布只上传 `dist/`；完整产物未包含源码、依赖、截图、研究文件、恢复材料或源码映射。

自动审批拒绝了批量清理原文件，理由是可能误删及回归。本次采用保留旧文件的方案，没有绕过该拒绝。原 `assets/` 中除数据与 core 以外的文件、根目录旧 SW／XML／manifest 是恢复材料；当前入口与构建不引用它们。原版还保存在 Git 基线及本机 `.tmp/react-baseline/`，原迁移阶段没有覆盖线上网站。
